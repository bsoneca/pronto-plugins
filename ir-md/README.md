# ir-md

`ir.md`, the app's `ir.html` as Markdown, written by `generate` (PRONTO-740 PP7). Pronto draws the
cards into `ir.html` but writes no Markdown beside it, so an app that wants one for a repository's
page, a diff or a model's context (apps `brawl-chess`, `studio`, `coach`, `aprende` do) either
wrote it by hand or ran the fork's writer. This plugin is that writer as a generate step; `ir.html`
stays the source and `ir.md` is never edited.

## Adopting it

```sh
bin/pronto-ir-md <app-dir>   # writes pronto/ir_md.cue and ir-md/ir-md.ts
```

Then run the app's `generate` and commit `ir.md`. The step (`ir-md`, priority 6, after pronto's writer
at 1, which draws the cards, so the Markdown holds the author's prose and the cards both) runs
`ir-md/ir-md.ts write .`: it reads `ir.html` and writes `ir.md` beside it, only when its text
changed, under the header `<!-- generated by pronto from ir.html: do not edit, edit ir.html -->`. An
app with no `ir.html` gets no `ir.md` and no error. `ir-md.ts write <app-dir> <source>` names another
source (`story.html` gives `story.md`).

What it keeps: headings, prose, lists, tables, code, links and images as Markdown; each design
object's id as an anchor (`<a id="Game"></a>`), so `ir.md#Game` lands where `ir.html#Game` does, with
its kind beside it; a card's chips on one line; the entity as a JSON block and a screen's paths as
JSON; `<details>` folded as GitHub folds them; mermaid as a mermaid block. A drawn picture (an SVG)
is not text: its caption stays, with a link to it in `ir.html`. Its output is byte for byte the
fork's `ir-md.ts` (it is that file), so an app that moves from the fork to this step keeps its `ir.md`.

Test: `deno test --no-config --allow-read --allow-write ir-md/ir-md_test.ts`.
