# pronto-perf

A plugin beside pronto, not part of it: the app holds the host's files and
its generate step re-applies the door's route pronto's writer regenerates. A
host-DOM hatch on every screen measures whatever draws the page, so a game needs
no code to be measured.

## What the app gets

| Path | Owner |
| --- | --- |
| `pronto/perf.cue` | regenerated: promtool and Vector pinned, the `generate` rule after pronto's writer |
| `perf_plugin.cue` | regenerated: the schema (`#Perf`), in the program's package |
| `perf_hatch.cue` | regenerated: the `perf` host-DOM hatch on every screen, the `perf-collector` container hatch, its cluster target, and the door's host peer |
| `shell/hatches/perf/perf.js` | regenerated: the reporter |
| `shell/hatches/perf/config.js` | regenerated by every generate: the sample and the histograms' boundaries |
| `perf/perf.nu` | regenerated: the generate step, the host collector, `perf report` |
| `perf_spec.cue` | seeded, then the app's: `perf: #Perf & {…}` |

## Adding it

From a bootstrapped pronto app whose four verbs are green:

```sh
${CLAUDE_PLUGIN_ROOT}/bin/pronto-perf .
./saytw --script tools.nu cue cmd generate ./pronto
./saytw --script tools.nu nu -c 'with-env {MISE_LOCKED: "0"} { ^mise install }'
./saytw --script tools.nu mise lock
./saytw generate
```

Then:

1. Set the SLOs in `perf_spec.cue` with the user: `slo.frames: {percent,
   under}` (default 95% of frames under 50ms), `slo.interaction` (75% under
   200ms), `slo.context: {percent}` (99.5% of sessions lose no WebGL context);
   `null` drops one. `sample` is the share of sessions that report (1 by
   default); `owner` labels the alerts.
2. A screen that declares hatches of its own names the reporter among them
   (`hatches: ["game", "perf"]`) and is listed in `_perfOwnHatches: ["play"]`;
   vet names any screen left without it.
3. Add both hatches to `ir.html` (`<section id="perf" data-kind="hatch">` and
   `<section id="perf-collector" data-kind="hatch">`), a decision saying why the
   app measures and what leaves the page, list the decision under
   `meta.decisions`, and re-pin `meta.ir.sha256`. If the app's privacy text
   promises no analytics, say what it now counts.
4. A game adds what only it knows, once a frame, on its screen:
   `screen.dispatchEvent(new CustomEvent("pronto:perf", {detail: {drawCalls,
   gpuMs, tier}}))` — three.js: `renderer.info.autoReset = false`, reset at the
   frame's start, read `renderer.info.render.calls` after the last pass; GPU time
   from `EXT_disjoint_timer_query_webgl2` where the browser has it. `tier` is a
   short lowercase name for the quality drawn at.
5. `./saytw generate && ./saytw lint && ./saytw test`, then `./saytw
   launch@local`, open the app with `?perf=overlay`, and read the collector with
   `./saytw --script tools.nu nu -c 'use perf/perf.nu; perf report
   http://127.0.0.1:<PERF_COLLECTOR_METRICS_PORT>/metrics'`.

An app whose program renders on request (pronto's `render` host peer) conflicts
with `perf_hatch.cue`'s `cluster: meta: hostPeers`: CUE cannot join two lists.
The host does not handle that yet; say so rather than editing the generated file.
